# 🏋️‍♂️ CrossFit Management Platform

Сучасна веб-платформа українською мовою для кросфіт-тренерів та атлетів з можливістю створення загальних та персональних тренувань (WOD), відправки результатів та ведення лідерборду.

Поточний Docker Compose запускає MongoDB та Keycloak командою
`docker compose up -d --build`. Сервіс `mongo-seed` автоматично перевіряє та
додає 233 вправи з `exercises.mongodb.json`, зберігаючи наявні записи.
Перевірка результату: `docker compose logs mongo-seed`.
[Інструкції з наповнення каталогу та локального запуску](scripts/README.md).

## 🛠 Технологічний стек

* **Backend:** Python 3.11, FastAPI, SQLAlchemy, Passlib (bcrypt), PyJWT, Pydantic.
* **Database:** PostgreSQL.
* **Frontend:** Modular Vanilla JavaScript (ES6+), HTML5, CSS3.
* **Infrastructure & Proxy:** Docker, Docker Compose, Nginx.

## 🚀 Основний функціонал

1. **Авторизація та Автотентифікація:**
   * Реєстрація та вхід за допомогою JWT-токенів.
   * Чітке розмежування ролей: **Coach (Тренер)** та **Athlete (Атлет)**.

2. **Панель Тренера (Coach Dashboard):**
   * Створення та редагування тренувань (WOD) із вибором типу (`AMRAP`, `FOR TIME`, `EMOM` тощо).
   * **Призначення персональних WOD:** можливість вибрати конкретного атлета (`athlete_id`) зі списку або створити загальне тренування для всіх.
   * Управління та видалення створених програм.

3. **Панель Атлета (Athlete Dashboard):**
   * Персоналізована стрічка тренувань (відображаються загальні WOD + власні персональні тренування з позначкою `🔒 Персональне`).
   * Відправка власних результатів за виконанні комплекси (із зазначенням Rx/Scaled).

4. **Фінанси та абонементи (Wallet):**
   * Тренер створює пакет для клієнта: вартість, кількість занять і фактично внесену суму. Часткова оплата та внесок `0 грн` підтримуються.
   * Ціна заняття обчислюється як `вартість пакета / кількість занять`; баланс — `внесені кошти - використані заняття × ціна заняття`. Від'ємний баланс означає борг.
   * У фінансовій таблиці показані використані заняття, внесена сума, ціна одного заняття, баланс і статус пакета. Пакети можна редагувати та видаляти; після першого списання тариф і кількість занять зафіксовані, але внесену суму можна оновити для обліку доплати.
   * Коли тренер відмічає персональне тренування як пройдене у стрічці WOD, система списує одну сесію з активного пакета. Повторне підтвердження не списує її вдруге.
   * Кнопка `Повернути` скасовує останнє списання та повертає пов'язане тренування у стан «не пройдено». Видалення WOD, за який уже списано сесію, автоматично повертає її до пакета перед видаленням картки, результату та події календаря. Ці зміни виконуються атомарно.

5. **Лідерборд (Leaderboard):**
   * Таблиця результатів для кожного WOD у реальному часі.

## 🏗 Архитектура та Маршрутизація

Всі запити від фронтенду проксуються через **Nginx** до **FastAPI**:

* HTTPS hostname, показаний `tailscale serve status`, — Головна сторінка у tailnet.
* `/api/` — Централізований префікс для всіх API-ендпоінтів:
   * `/api/token` — Вхід у систему.
   * `/api/users/register` — Реєстрація за одноразовим запрошенням.
   * `/api/workouts/` — Стрічка та управління WOD.
   * `/api/workouts/{workout_id}/complete` — Підтвердження тренером проходження персонального WOD і списання сесії.
   * `/api/subscriptions/` — Перегляд пакетів; `POST` створює пакет з фактичним депозитом.
   * `/api/subscriptions/{sub_id}` — `PUT` редагує пакет, `DELETE` видаляє його (тільки тренер-власник).
   * `/api/subscriptions/{sub_id}/undo-session` — Повернення останнього списання.
   * `/api/workouts/{workout_id}` — `DELETE` видаляє WOD і повертає пов'язану сесію, якщо її було списано.
   * `/api/users/athletes` — Отримання списку атлетів (тільки для тренерів).
   * `/api/results/` — Відправка та перегляд лідерборду.

## Безпечний запуск через Tailscale

Docker публікує Nginx лише на loopback `127.0.0.1:8090`; Tailscale Serve надає HTTPS доступ тільки всередині tailnet. PostgreSQL і FastAPI не мають опублікованих host-портів. Не вмикайте Tailscale Funnel; обмежте доступ правилами ACL у tailnet.

1. Створіть локальне налаштування з шаблону: `cp .env.example .env`.
2. Вкажіть у `.env` випадкові URL-safe `POSTGRES_PASSWORD` і `SECRET_KEY` щонайменше з 32 байтів. Значення генерується командою:
   ```bash
   python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
   ```
   Згенеруйте окреме значення для кожного секрету. Не надсилайте `.env` іншим і не додавайте його в Git.
3. Для вже створеної БД спершу встановіть той самий новий пароль усередині PostgreSQL:
   ```bash
   docker exec -it crossfit_db psql -U crossfit_user -d crossfit_db -c "ALTER ROLE crossfit_user WITH PASSWORD 'НОВИЙ_POSTGRES_PASSWORD'"
   ```
   Для нової бази цей крок не потрібен. Зміна змінної Compose сама не оновлює пароль у наявному volume.
4. Пересоздайте сервіси: `docker compose up -d --build --force-recreate`.
5. Увімкніть HTTPS proxy командою `tailscale serve --bg 8090`, перевірте hostname через `tailscale serve status`, і передайте цей HTTPS URL учасникам tailnet. Додайте їх до tailnet та дозвольте доступ через ACL. Не використовуйте Funnel і не відкривайте порт на роутері.

Тренер створює одноразове запрошення в панелі WOD і передає код атлету приватно. Код діє 7 днів та стає недійсним після реєстрації. Пароль має містити щонайменше 12 символів. Зміна `SECRET_KEY` анулює поточні JWT, тому користувачам потрібно буде увійти знову.

Не запускайте `docker compose down -v` для звичайного оновлення: `-v` видалить volume бази та тестові дані.

## Оновлення схеми бази

Для нових інсталяцій таблиці створюються автоматично, але версії схеми зберігаються в Alembic. Перед оновленням production-бази зробіть резервну копію та виконайте міграції з backend-контейнера:

```bash
docker compose run --rm backend alembic upgrade head
```

Нові атлети автоматично прив'язуються до тренера, який створив invitation-код. Уже існуючих атлетів потрібно перевірити та прив'язати окремо перед увімкненням суворої ізоляції даних.

Під час старту backend також додає wallet-колонки до наявних таблиць `subscriptions` і `workouts`. Для старих пакетів, у яких сума фактичної оплати раніше не зберігалася, міграція встановлює `paid_amount` рівним вартості пакета; перевірте ці значення та виправте їх у фінансовій таблиці за потреби.
